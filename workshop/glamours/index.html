Glamours userscripts · userstyles · local, no tracking

Re-enchant other people's websites

Some web apps you don't get to choose — you just get to stare at them all day. A glamour is a small illusion spell: a few lines of CSS or JavaScript your browser applies on arrival, so the site looks and behaves the way it always should have. This page collects ours — each one documented: what it does, how it works, and why it's nice.

📖 The spellbook

🐒 Step 1 · Pick a userscript manager

A userscript manager is a browser extension that keeps your scripts, decides which sites they run on and updates them. Four are worth knowing. They all read the same .user.js format, so a glamour from this page works in any of them — the differences are the browser you use, whether the code is open source, and how many extras you want.

🐵 Tampermonkey the default choice

Chrome · Edge · Safari · Opera · Firefox. By far the most used manager, and the one every script is tested against. Built-in editor, automatic update checks, ZIP import/export and sync through Google Drive, Dropbox or OneDrive.

The catch: it is free but not open source — the Firefox listing is “All Rights Reserved”. On Chrome-based browsers it also needs one extra permission click (step 2 below).

Best compatibility & most features · closed source · tampermonkey.net ↗

🟣 Violentmonkey open source pick

Chrome · Edge · Firefox · Opera · Firefox for Android. MIT-licensed and developed in the open, so anyone can audit exactly what the extension does with its “access all websites” permission — which matters for something that can read every page you visit.

Runs most Greasemonkey and Tampermonkey scripts unchanged, syncs through Dropbox, OneDrive, Google Drive or any WebDAV server, and asks for fewer permissions (downloads are optional).

Same job, auditable code · slightly fewer conveniences · violentmonkey.github.io ↗

🐒 Greasemonkey the original

Firefox only. The 2005 extension that invented all of this: the .user.js file, the ==UserScript== header, the @match rules. Still maintained, still MIT.

The catch: version 4 moved to the modern asynchronous GM.* API and dropped several classic GM_* functions, so a fair number of older scripts in the wild run in Tampermonkey and Violentmonkey but not here. (Ours use neither — they ask for @grant none.)

Historic & lean · Firefox only · patchiest script compatibility · greasespot.net ↗

🔥 FireMonkey scripts + styles in one

Firefox only (Android support experimental). Handles both userscripts and userstyles, so it replaces a Greasemonkey-type extension and Stylus at once — handy for this page, where several glamours ship a CSS-only version.

Built on Firefox’s dedicated userScripts API rather than generic injection, supports both the old GM_* and new GM.* styles, MPL-2.0 licensed and contains no tracking. It is much smaller than the others, so it gets less real-world testing.

Lightweight, one extension for both · Firefox only · small user base · addons.mozilla.org ↗

Short version: on Chrome or Edge, Tampermonkey unless you want open source, then Violentmonkey. On Firefox, Violentmonkey for the widest script compatibility, FireMonkey if you also want your userstyles in the same place, Greasemonkey if you like the original. Whatever you pick, install one — two managers will both run the same script twice.

🔓 Step 2 · Allow userscripts (Chrome-based browsers)

Since Tampermonkey 5.3, a Chrome-based browser will not execute userscripts until you grant permission. Straight from the Tampermonkey FAQ (Q209): you need either the “Allow User Scripts” toggle (available in Chrome 138+ in the extension’s settings) or Developer Mode.

  1. Right-click the Tampermonkey icon in the toolbar and choose Manage Extension.
  2. Find the “Allow User Scripts” toggle and switch it on. That enables the userScripts API for Tampermonkey. On older Chrome builds without the toggle, turn on Developer mode at the top of chrome://extensions instead.

Why is this necessary? Userscripts use a two-step authorisation: the userScripts permission plus the toggle or Developer Mode. The permission on its own shows no warning when the extension is installed, so Google added the second step to make sure running arbitrary userscripts is a decision you took knowingly. Firefox needs none of this.

✨ Step 3 · Cast it

  1. Click an “Install userscript” button above. Any link ending in .user.js makes your manager pop its install screen automatically — review the code, confirm, done. A .user.css link does the same in Stylus or FireMonkey.
  2. Visit the site. The glamour applies itself on every page load. Look for its settings pill to toggle individual tweaks.
  3. Updates are automatic. Each script carries an @updateURL pointing back here, so your manager picks up new versions on its own.

Trust rule: only ever install userscripts you (or someone you trust) have read. A userscript runs with full access to the pages it matches — which is precisely why it can fix them. Everything here is plain, commented source that makes no network requests of its own; the only privileges asked for are the two storage calls that remember your own settings between ConnectWise's two domains.

🧪 No userscript manager? Six other ways to cast

A manager is the most comfortable wand, but it is not the only one. If extensions are locked down on your machine, or a tweak is pure CSS anyway, pick by what it needs and what you are allowed to install:

🖌️ Stylus best for CSS-only

The Stylus extension applies user styles — CSS only, no script execution, so it needs far less trust and fewer permissions. Every glamour here that has a .user.css file installs into Stylus with one click and can be toggled per site. On Firefox, FireMonkey does the same job in the same extension as your scripts.

Persistent · auto-applies · can't do JS features (panels, login helpers)

🔖 Bookmarklet zero extensions

A bookmark whose URL is javascript:… code that injects the CSS when clicked. Nothing to install — works even where extensions are forbidden. The catch: you click it once per visit, and sites with a strict style-src CSP can refuse it.

No install rights needed · manual, per-tab, per-visit · each card below offers a drag-to-bookmark version

🛠️ DevTools local overrides built into the browser

Chrome/Edge can persist your CSS edits across reloads: DevTools → Sources → Overrides → pick a local folder → edit any stylesheet. Firefox has Style Editor for the session. Great for prototyping a glamour before packaging it; clumsy as a daily driver.

No extension · survives reloads (Chromium) · per machine, fiddly

🛡️ uBlock Origin cosmetic filters you may already have it

If a tweak only needs to hide things, uBlock Origin does it natively: dashboard → My filters → eu.myconnectwise.net##.annoying-thing. No styling or behaviour changes, but zero extra software if it's already installed.

Hide-only · syncs with uBlock backup · can't recolour or add features

🦊 Firefox userContent.css no extension at all

Firefox natively loads chrome/userContent.css from your profile folder at startup. Wrap rules in @-moz-document domain("eu.myconnectwise.net") { … }, flip toolkit.legacyUserProfileCustomizations.stylesheets to true in about:config, restart.

Pure browser feature · CSS only · needs a restart per change

🔍 Per-site zoom the humble classic

Ctrl++/− is remembered per origin by every browser. It's the no-code answer to “this app's text is too small” — and the honest baseline any density tweak should beat.

Zero setup · scales everything equally, fixes nothing structural

For a whole team: IT can force-install a manager (Tampermonkey, Violentmonkey) or Stylus with a preloaded script list via managed browser policies (ExtensionInstallForcelist + each extension's managed storage) — one glamour, everyone's browser. And for completeness: ConnectWise Manage itself offers no theming, custom-CSS or density options server-side, which is exactly why this page exists.
